# 2026-07-31

## Server: always-on SSE / streamable-http transport (v0.2.0)

Context: with the default `stdio` transport the MCP client spawns the server per
session, so the WebSocket bridge — and therefore the Firefox extension
connection — only lives while a client session is open. Goal: keep the browser
connection available continuously.

Note: an earlier, incomplete SSE attempt was left uncommitted in the working
tree. Per request it was reverted with `git restore` (back to `0fa0e1c`) and the
change was redone cleanly and validated.

### Changes

- `mcp-server/src/firefox_browser_mcp/server.py`
  - New CLI args: `--transport {stdio,sse,streamable-http}` (env
    `FBMCP_TRANSPORT`, default `stdio`), plus `--http-host`/`--http-port` (env
    `FBMCP_HTTP_HOST`/`FBMCP_HTTP_PORT`, default `127.0.0.1:8000`).
  - New `_run_http()` helper: builds `mcp.sse_app()` / `mcp.streamable_http_app()`
    and **wraps the app's lifespan** so the WebSocket bridge starts/stops with
    the HTTP server process (not merely per MCP client session), then runs it via
    uvicorn. `stdio` path unchanged (`mcp.run()`).
- `mcp-server/src/firefox_browser_mcp/bridge.py`
  - `start()`/`stop()` are now **reference-counted / idempotent** so the bridge
    binds the port once even though both the HTTP app lifespan and each
    per-session MCP lifespan call them; the port is torn down only on final
    release.
- Version bump: `pyproject.toml` + `__init__.py` → **0.2.0**.
- `mcp-server/.gitignore`: also ignore `.venv*/` and `venv/` (a stray test venv
  had broken an sdist build).

### Verification

- `py_compile` OK for `server.py` and `bridge.py`.
- Clean-venv run of `--transport sse --http-port 8765 --port 9010`: the WS bridge
  is **listening at startup before any `/sse` connection**, a WS client connects
  immediately (`WS BRIDGE CONNECT OK`), and `GET /sse` returns
  `200 text/event-stream`.
- `--transport streamable-http` run: WS bridge up at startup, HTTP up, session
  manager started (lifespan wrapping preserved), and a `POST /mcp` `initialize`
  returned a valid MCP result.
- `uv build` (sdist + wheel) succeeded; `twine check` PASSED for both.
